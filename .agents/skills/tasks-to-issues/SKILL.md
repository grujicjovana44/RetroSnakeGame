# Tasks to Issues

- Read `TASKS.md` and preserve task IDs, dependencies, acceptance criteria, and evidence links.
- Generate one local issue draft per actionable task, grouped by milestone when useful.
- Include context, proposed scope, acceptance checklist, validation, and open questions.
- Do not create GitHub, Linear, or other external issues without explicit user authorization and an available connector.
- Keep issue drafts synchronized with the task list; do not invent work outside the approved scope.
