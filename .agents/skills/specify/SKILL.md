# Specify

- State user value, functional requirements, non-functional requirements, constraints, and explicit out-of-scope items.
- Give every requirement a stable identifier and observable acceptance criteria.
- Include normal, boundary, negative, and failure cases.
- Separate behavior from implementation choices unless the constitution requires a technology constraint.
- Link requirements to evidence expectations; do not claim completion in the specification.
