# Tasks

- Create small tasks with IDs, dependencies, affected files, acceptance criteria, and validation commands.
- Order tasks so contracts and tests precede dependent implementation where practical.
- Include documentation, evidence, and rollback/review tasks when relevant.
- Keep each task narrow enough to review in one change.
- Do not mark a task complete until its acceptance evidence exists.
